# M0-2 数据分级与敏感检测规则

配套实现：`privacy/patterns.py`。本文件定义策略，代码只负责可判定的部分，两者必须同步修改。

## 1. 分级定义

沿用 `docs/architecture.md` 5.6，不新增级别。

| 级别 | 范围 | 第一阶段处理 |
| --- | --- | --- |
| `LOCAL_ONLY` | 人格、偏好、情景记忆、敏感文件索引 | 默认，全部数据 |
| `ENCRYPTED_SYNC` | 多设备同步的密文 | 预留，不实现 |
| `CLOUD_ENHANCED` | 用户显式授权的无状态推理 | 预留；如接云模型，只发本次组装的最小上下文 |

分级描述的是**数据的去向**，敏感级描述的是**数据本身的风险**，两者正交：

- 一条 `high` 敏感的身份证号，去向仍是 `LOCAL_ONLY`
- 一条 `low` 敏感的写作偏好，走 `CLOUD_ENHANCED` 时也必须先脱敏

## 2. 检测边界（必须先认清）

| 类别 | 可判定性 | 处理方式 |
| --- | --- | --- |
| 结构化凭证（手机号、证件号、银行卡、邮箱、密钥、密码） | 高，正则 + 校验位可判 | 代码拦截，命中即处理 |
| 语义风险（住址、病史、财务、人际关系、涉密工作内容） | 低，依赖上下文 | 规则不判定，靠摘要链路与用户确认 |

这条边界要写进文档，是因为**不能假装正则能识别「我家住在朝阳区某某小区 3 号楼」**。语义类一旦误判成安全，后果比漏判更严重。第一阶段对语义类的策略是：不主动写入情景记忆，只允许在用户显式要求时写入，并在写入时标注 `sensitivity = high`。

## 3. 规则清单

| kind | 匹配对象 | 敏感级 | 校验 | 样例 |
| --- | --- | --- | --- | --- |
| `id_card` | 中国大陆 18 位身份证 | high | 加权校验位 | `110101199003071234` |
| `bank_card` | 16–19 位连续数字 | high | Luhn | `6222021234567890123` |
| `phone` | 中国大陆手机号 | high | 号段 `1[3-9]` | `13812345678` |
| `api_key` | `sk-` / `ghp_` / `AKIA` / `key=` 形式 | high | 无 | `sk-abcdefghijklmnop` |
| `password` | 「密码是…」「password=…」 | high | 无 | `密码是 abc12345` |
| `email` | 邮箱地址 | medium | 无 | `a@b.com` |

校验位是必须的，不是锦上添花：16 位纯数字在订单号、流水号里极常见，不做 Luhn 会把大量正常文本误标为银行卡，导致 `high` 拦截泛滥，最后用户学会忽略告警。

## 4. 写入策略

按「敏感级 × 来源」决定是否落库。这张表是 W2-3、W2-4 的实现依据。

| 敏感级 | `user_explicit` | `inferred` |
| --- | --- | --- |
| low | 直接写入 | 直接写入 |
| medium | 直接写入，摘要中保留 | 写入待确认列表 |
| high | 用户显式确认后写入，记 `confirmed_by_user = true` | **不写入**，仅当次会话内存可用 |

补充三条：

1. `high` 数据不进入 `EpisodicMemory.summary`，也不进入日志；写入的是脱敏后的占位文本。
2. `raw_ref` 指向的 `ConversationTurn.content` 同样要脱敏，否则从 turn 能反推出记忆内容。
3. 删除记忆时同步删除对应 `vec_*`；若脱敏前文本曾进入临时缓存，缓存必须随请求结束清空。

## 5. 脱敏输出

`redact()` 的占位格式为 `[REDACTED:<kind>]`，例如：

```
原文：我手机号 13812345678，邮箱 a@b.com
脱敏：我手机号 [REDACTED:phone]，邮箱 [REDACTED:email]
```

约定：

- 占位符保留 `kind`，便于排障时知道命中了哪类规则，但不保留任何原文片段（包括首尾字符）
- 不做「保留前 3 后 4」这类掩码，因为 11 位手机号保留 7 位等于泄漏
- 日志只写 `kind` 与计数，不写位置偏移量以外的任何信息

## 6. 已知漏报与误报

| 类型 | 情况 | 阶段 |
| --- | --- | --- |
| 漏报 | 用户口述手机号（「一三八一二三四五六七八」） | 不处理，规则无能为力 |
| 漏报 | 语义类风险（住址、病史） | 靠摘要链路与用户确认 |
| 漏报 | 国际号码、港澳台证件 | 第一阶段不覆盖 |
| 误报 | Luhn 恰好通过的订单号 | 可接受，走用户确认 |
| 误报 | 「密码是」出现在教学、讨论语境 | 可接受，宁可多拦 |

误报的代价是弹一次确认，漏报的代价是隐私泄漏。第一阶段一律倾斜到多拦。

## 7. 与代码的对应

| 接口 | 行为 |
| --- | --- |
| `scan(text) -> list[Finding]` | 返回全部命中，按位置升序，重叠只保留先出现者 |
| `max_sensitivity(text) -> Sensitivity` | 最高命中级别，无命中返回 `low` |
| `redact(text) -> str` | 按第 5 节规则替换 |

规则增删改必须同时更新本文件第 3 节与 `tests/test_privacy.py`。
